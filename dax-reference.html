01 Le pivot

Toutes les autres fonctions de cette page existent pour modifier ce que CALCULATE voit. Comprendre celle-ci en premier rend le reste évident.

CALCULATE Fonction centrale

Évalue une expression après avoir modifié le contexte de filtre. Rien ne se calcule "dans le vide" — CALCULATE change d'abord les règles, puis laisse l'agrégation s'exécuter dans ce nouveau cadre.

CALCULATE(<expression>, <filtre1>, <filtre2>, …)

Comportement par défaut

Un filtre sur une colonne déjà filtrée par le contexte existant la remplace. Sur une colonne différente, il s'ajoute.

Effet de bord

Dans un contexte de ligne (colonne calculée, SUMX), CALCULATE déclenche la context transition : chaque colonne de la ligne devient un filtre.

À retenir

Toutes les fonctions ci-dessous ne servent qu'à une chose : changer ce que CALCULATE filtre, avant qu'il n'agrège.

02 Supprimer des filtres

Ces fonctions élargissent la vue : elles retirent tout ou partie du contexte de filtre pour calculer une référence, un total général ou une part du tout.

ALL Modificateur de filtre

Supprime les filtres sur une table entière ou une colonne précise. Sert à "voir au-delà" du filtre actuel — total général, référence globale, dénominateur d'un pourcentage.

ALL(Table) — retire tous les filtres de la table
ALL(Table[Colonne]) — retire le filtre sur cette colonne seulement

Usage classique

Dénominateur d'un % du total : CALCULATE(SUM(…), ALL(Table)).

Piège

ALL(Table) et ALL(Colonne) n'ont pas le même rayon d'action — le premier ignore aussi les autres colonnes filtrées.

ALLEXCEPT Modificateur de filtre

Supprime tous les filtres d'une table, sauf ceux listés en exception. Raccourci pratique quand on veut garder un seul axe de filtrage actif.

ALLEXCEPT(Table, Table[ColonneÀGarder])
Équivalence : ALLEXCEPT(T, T[X]) revient à écrire ALL(T) puis à réintroduire manuellement le filtre sur X — c'est un raccourci d'écriture, pas un mécanisme différent.
ALLSELECTED Modificateur de filtre

Retire les filtres du visuel courant, mais conserve ceux venant des slicers et des interactions externes. Utile pour un "total visible" qui respecte la sélection de l'utilisateur sans respecter chaque ligne du tableau.

ALLSELECTED() / ALLSELECTED(Table ou Colonne)

Différence avec ALL

ALL ignore tout, y compris les slicers. ALLSELECTED garde ce que l'utilisateur a choisi hors du visuel.

REMOVEFILTERS Modificateur de filtre

Équivalent moderne et plus explicite de ALL utilisé comme suppresseur de filtre — le nom dit directement l'intention, ce qui rend le DAX plus lisible en relecture.

REMOVEFILTERS(Table) ou REMOVEFILTERS(Colonne)

03 Ajouter sans remplacer

À l'inverse du groupe précédent, ces fonctions affinent le contexte au lieu de l'effacer — elles restreignent l'ensemble des lignes visibles.

KEEPFILTERS Modificateur de filtre

Empêche le comportement par défaut de CALCULATE. Au lieu de remplacer un filtre existant sur la même colonne, le nouveau filtre s'ajoute — l'intersection des deux s'applique.

CALCULATE(expr, KEEPFILTERS(Table[Colonne] = valeur))
Sans KEEPFILTERS, une ligne "Table" filtrée par CALCULATE sur "Chaise" afficherait quand même un résultat sur la ligne "Table" du visuel. Avec KEEPFILTERS, l'intersection Table ∩ Chaise est vide → résultat 0.
FILTER Agrégation / calcul

Retourne une table restreinte aux lignes qui vérifient une condition. S'utilise en argument de CALCULATE quand le filtre est trop complexe pour une simple expression booléenne.

FILTER(Table, condition)

Exemple

CALCULATE(SUM(Ventes[Montant]), FILTER(Ventes, Ventes[Montant] > 100))

Coût

Parcourt la table ligne à ligne — à réserver aux conditions qu'une expression simple ne peut pas exprimer.

04 Agréger ligne à ligne

Trois fonctions d'usage quotidien, indépendantes du mécanisme de filtrage mais omniprésentes dans les mêmes mesures.

SUMX Agrégation / calcul

Parcourt une table ligne par ligne, évalue une expression pour chacune, puis additionne les résultats. Indispensable dès que le calcul par ligne n'est pas une simple colonne existante (ex : quantité × prix unitaire).

SUMX(Table, expression_par_ligne)

Exemple

SUMX(Ventes, Ventes[Quantité] * Ventes[PrixUnitaire])

DIVIDE Agrégation / calcul

Division sécurisée : retourne un résultat alternatif (0 par défaut) au lieu d'une erreur quand le dénominateur vaut zéro ou est vide. À utiliser systématiquement à la place de l'opérateur /.

DIVIDE(numérateur, dénominateur, [résultat_si_zéro])
RANKX Agrégation / calcul

Calcule le rang d'une valeur au sein d'une table, selon une expression de tri. Utile pour classer produits, régions ou clients par performance.

RANKX(Table, expression, [valeur], [ordre], [égalités])

Exemple

RANKX(ALL(Produit), CALCULATE(SUM(Ventes[Montant])))

Piège fréquent

Oublier ALL autour de la table de classement — sans lui, chaque ligne se retrouve seule dans son propre contexte et le rang vaut toujours 1.

05 Chronologie

Ces fonctions ne fonctionnent correctement qu'avec une vraie table de dates, marquée comme telle dans le modèle, sans trou sur la plage couverte.

CALENDAR Agrégation / calcul

Génère une table à une colonne (Date) contenant une ligne par jour entre deux dates. C'est la fonction qui construit la table de dates elle-même — préalable indispensable à toutes les fonctions ci-dessous.

CALENDAR(date_début, date_fin) — bornes fixes
CALENDARAUTO([mois_fin_année]) — bornes déduites des dates déjà présentes dans le modèle

1. Créer la table

Nouvelle table calculée, dans la vue Modèle ou Données : Modélisation > Nouvelle table.

2. Écrire la formule

Dates = CALENDAR(DATE(2020,1,1), DATE(2026,12,31)), ou plus simple : Dates = CALENDARAUTO()

3. Enrichir avec des colonnes

Ajouter Année, Mois, Trimestre, Jour de semaine… en colonnes calculées sur cette même table.

4. Marquer comme table de dates

Clic droit sur la table > Marquer comme table de dates > choisir la colonne Date. Sans cette étape, les fonctions de Time Intelligence peuvent donner des résultats faux.

5. Relier au modèle

Créer la relation Dates[Date] → Fait_Ventes[DateCommande] (1:*), filtrage à sens unique, comme n'importe quelle dimension du schéma en étoile.

Année = YEAR(Dates[Date]) Mois = FORMAT(Dates[Date], "MMMM") NuméroMois = MONTH(Dates[Date]) Trimestre = "T" & FORMAT(Dates[Date], "Q") JourSemaine = FORMAT(Dates[Date], "dddd")
Pourquoi une table dédiée plutôt que la date déjà présente dans Fait_Ventes : une table de dates indépendante couvre une plage continue (aucun jour manquant, même sans vente ce jour-là), peut être partagée par plusieurs tables de faits, et sert d'ancrage unique pour tout le Time Intelligence du modèle.
SAMEPERIODLASTYEAR Modificateur de filtre

Génère une table de dates décalée d'un an en arrière, que CALCULATE utilise ensuite comme nouveau filtre sur la table de dates. Base de toute comparaison "vs année précédente".

CALCULATE(SUM(Ventes[Montant]), SAMEPERIODLASTYEAR(Dates[Date]))
DATEADD Modificateur de filtre

Décale la table de dates d'un nombre d'unités choisi (jour, mois, trimestre, année) — plus flexible que SAMEPERIODLASTYEAR, qui n'est qu'un cas particulier de DATEADD sur un an.

DATEADD(Dates[Date], -1, MONTH)
TOTALYTD Agrégation / calcul

Cumul depuis le début de l'année civile (ou fiscale) jusqu'à la dernière date du contexte de filtre. Combine en une seule fonction une agrégation et un filtre implicite sur la table de dates.

TOTALYTD(SUM(Ventes[Montant]), Dates[Date])
DATESYTD Modificateur de filtre

Retourne une table des dates depuis le début de l'année jusqu'à la dernière date du contexte, au lieu d'un résultat direct comme TOTALYTD. S'utilise comme argument de CALCULATE quand on veut plus de contrôle que TOTALYTD n'en offre.

CALCULATE(SUM(Ventes[Montant]), DATESYTD(Dates[Date]))
Mêmes cousines pour d'autres granularités : DATESQTD (depuis le début du trimestre) et DATESMTD (depuis le début du mois).
PARALLELPERIOD Modificateur de filtre

Décale la table de dates d'un nombre entier de périodes complètes (mois, trimestre, année) — contrairement à DATEADD, qui décale jour pour jour, PARALLELPERIOD ramène toujours la période entière correspondante.

PARALLELPERIOD(Dates[Date], -1, QUARTER)
Différence concrète : avec un contexte filtré sur les 10 premiers jours de février, DATEADD(…, -1, MONTH) retourne les 10 premiers jours de janvier (même tranche décalée), tandis que PARALLELPERIOD(…, -1, MONTH) retourne tout le mois de janvier — 31 jours, peu importe la tranche filtrée au départ.

Exemple à tester dans DAX.do

DEFINE TABLE Ventes = ADDCOLUMNS( CALENDAR(DATE(2026,1,1), DATE(2026,2,28)), "Montant", MOD(DAY([Date]), 4) * 25 + 40 ) EVALUATE ROW( "Ventes réelles (1-10 fév)", CALCULATE( SUM(Ventes[Montant]), Ventes[Date] >= DATE(2026,2,1) && Ventes[Date] <= DATE(2026,2,10) ), "DATEADD -1 mois", CALCULATE( CALCULATE(SUM(Ventes[Montant]), DATEADD(Ventes[Date], -1, MONTH)), Ventes[Date] >= DATE(2026,2,1) && Ventes[Date] <= DATE(2026,2,10) ), "PARALLELPERIOD -1 mois", CALCULATE( CALCULATE(SUM(Ventes[Montant]), PARALLELPERIOD(Ventes[Date], -1, MONTH)), Ventes[Date] >= DATE(2026,2,1) && Ventes[Date] <= DATE(2026,2,10) ), "Vérification : tout janvier (réel)", CALCULATE( SUM(Ventes[Montant]), Ventes[Date] >= DATE(2026,1,1) && Ventes[Date] <= DATE(2026,1,31) ) )

Pourquoi le CALCULATE imbriqué

Le CALCULATE extérieur simule le filtre d'un visuel (1-10 février). Le CALCULATE intérieur applique DATEADD/PARALLELPERIOD sur ce contexte déjà établi — exactement le mécanisme d'une mesure de comparaison temporelle dans un vrai rapport.

Résultat attendu

DATEADD ≠ PARALLELPERIOD : le premier reste sur 10 jours, le second ramène les 31 jours de janvier, identique à la ligne de vérification.

FIRSTDATE / LASTDATE Agrégation / calcul

Retournent respectivement la première et la dernière date visibles dans le contexte de filtre actuel. Utiles pour afficher un solde de fin de période (stock, effectif) plutôt qu'une somme.

CALCULATE(SUM(Stock[Quantité]), LASTDATE(Dates[Date]))

06 Relations & sécurité

Fonctions rencontrées dès qu'on sort du schéma en étoile standard — relations inactives, recherches croisées, sécurité au niveau ligne.

USERELATIONSHIP Modificateur de filtre

Active ponctuellement, dans une seule mesure, une relation marquée comme inactive dans le modèle. Utile quand deux relations existent entre les deux mêmes tables (ex : date de commande vs date de livraison) et qu'une seule peut être active à la fois.

CALCULATE(SUM(Ventes[Montant]), USERELATIONSHIP(Ventes[DateLivraison], Dates[Date]))
LOOKUPVALUE Agrégation / calcul

Recherche une valeur dans une table selon une ou plusieurs conditions de correspondance — l'équivalent DAX d'un RECHERCHEV multi-critères. Fréquent dans les règles de sécurité au niveau ligne (RLS).

LOOKUPVALUE(Table[ColonneRésultat], Table[ColonneClé], valeur_recherchée)
USERPRINCIPALNAME Agrégation / calcul

Retourne l'identifiant (généralement l'e-mail) de l'utilisateur connecté au Power BI Service. Pierre angulaire du RLS dynamique : combinée à une table de mapping et LOOKUPVALUE, elle évite de créer un rôle par utilisateur.

[Email] = USERPRINCIPALNAME()

07 Tester le contexte

Avant d'agir sur un contexte de filtre, on a souvent besoin de savoir ce qu'il contient — une valeur, plusieurs, ou aucune.

VALUES Agrégation / calcul

Retourne les valeurs distinctes d'une colonne visibles dans le contexte de filtre actuel, sous forme de table. Sert de base à beaucoup de fonctions qui attendent une table plutôt qu'une valeur scalaire.

VALUES(Table[Colonne])
SELECTEDVALUE Agrégation / calcul

Retourne la valeur unique d'une colonne si le contexte n'en montre qu'une, sinon une valeur par défaut. Remplace avantageusement la combinaison IF + HASONEVALUE + VALUES, en une seule fonction.

SELECTEDVALUE(Table[Colonne], [valeur_par_défaut])
HASONEVALUE Agrégation / calcul

Teste si une colonne n'affiche qu'une seule valeur distincte dans le contexte actuel. Retourne VRAI/FAUX — s'emploie typiquement dans un IF pour choisir un affichage selon le niveau de détail sélectionné.

HASONEVALUE(Table[Colonne])
ISBLANK / ISFILTERED Agrégation / calcul

ISBLANK teste si une expression est vide. ISFILTERED teste si une colonne est activement filtrée (par opposition à seulement présente dans le modèle). Deux tests de garde fréquents avant un calcul.

ISBLANK(expression) · ISFILTERED(Table[Colonne])

08 Logique conditionnelle

Deux fonctions pour brancher un calcul selon une condition — la seconde évite l'empilement d'IF imbriqués.

IF Agrégation / calcul

Condition simple à deux branches. Au-delà de deux ou trois conditions imbriquées, la lisibilité chute vite — c'est le signal pour passer à SWITCH.

IF(condition, valeur_si_vrai, valeur_si_faux)
SWITCH Agrégation / calcul

Évalue une expression et la compare à une liste de valeurs possibles, avec un résultat associé à chacune. Remplace une chaîne d'IF imbriqués par une structure plate et lisible.

SWITCH(expression, valeur1, résultat1, valeur2, résultat2, …, [résultat_par_défaut])
Variante fréquente : SWITCH(TRUE(), condition1, résultat1, condition2, résultat2, …) — reproduit un IF imbriqué tout en gardant la lisibilité de SWITCH.

09 Agrégations complémentaires

Les autres fonctions de comptage et de classement qu'on croise aussi souvent que SUM et SUMX.

COUNTROWS Agrégation / calcul

Compte les lignes d'une table — souvent une table de faits filtrée, ou le résultat d'un FILTER/VALUES. Plus rapide que COUNT sur une colonne quand seul le nombre de lignes compte.

COUNTROWS(Table)
COUNTX / AVERAGEX / MAXX / MINX Agrégation / calcul

Les cousins de SUMX : même principe d'itération ligne à ligne sur une table, suivi respectivement d'un comptage, d'une moyenne, d'un maximum ou d'un minimum des résultats obtenus.

AVERAGEX(Ventes, Ventes[Quantité] * Ventes[PrixUnitaire])
DISTINCTCOUNT Agrégation / calcul

Compte le nombre de valeurs distinctes d'une colonne dans le contexte actuel — par exemple le nombre de clients uniques ayant acheté, plutôt que le nombre de lignes de vente.

DISTINCTCOUNT(Ventes[ID_Client])
TOPN Agrégation / calcul

Retourne les N premières lignes d'une table selon un critère de tri. Combinée à SUMX, elle permet de calculer un total limité aux meilleurs éléments (ex : somme des 5 plus gros clients).

TOPN(5, Clients, [Ventes Totales], DESC)

10 Relations entre tables

Trois façons de traverser une relation du modèle sans forcément passer par CALCULATE.

RELATED Agrégation / calcul

Récupère une colonne depuis la table liée du côté « un » d'une relation, depuis un contexte de ligne du côté « plusieurs ». Utilisable dans une colonne calculée sans écrire de CALCULATE.

RELATED(Dim_Produit[Catégorie])
RELATEDTABLE Agrégation / calcul

Le sens inverse de RELATED : depuis le côté « un », retourne la table des lignes liées côté « plusieurs ». S'utilise typiquement avec COUNTROWS pour compter des lignes liées (ex : nombre de commandes par client).

COUNTROWS(RELATEDTABLE(Fait_Ventes))
TREATAS Modificateur de filtre

Applique les valeurs d'une table comme filtre sur les colonnes d'une autre, sans qu'une relation physique existe entre elles dans le modèle — crée une relation virtuelle valable pour la durée du calcul.

CALCULATE(SUM(Ventes[Montant]), TREATAS(VALUES(TableExterne[Région]), Dim_Région[Nom_Région]))

11 Écriture & texte

Une structure et une fonction qui n'affectent pas le filtrage, mais qui rendent les mesures plus lisibles et plus expressives.

VAR / RETURN Structure

Stocke le résultat intermédiaire d'une expression dans une variable nommée, réutilisable ensuite sans être recalculée. Rend les mesures complexes lisibles et évite les répétitions du même sous-calcul.

VAR TotalActuel = SUM(Ventes[Montant]) VAR TotalAnnéePrécédente = CALCULATE(SUM(Ventes[Montant]), SAMEPERIODLASTYEAR(Dates[Date])) RETURN DIVIDE(TotalActuel - TotalAnnéePrécédente, TotalAnnéePrécédente)
CONCATENATEX Agrégation / calcul

Concatène en une seule chaîne les valeurs d'une expression évaluée sur plusieurs lignes, avec un séparateur au choix. Utile pour afficher une liste (ex : les produits d'une commande) dans une seule cellule.

CONCATENATEX(RELATEDTABLE(Détail_Commande), Détail_Commande[Produit], ", ")
